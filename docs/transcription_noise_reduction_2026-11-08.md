# 文字起こし前の音声クリーンアップとノイズ除去 (2026-11-08)

音声認識に送る音声の質を上げる変更と、その評価のまとめ。

| 節 | 変更 | 既定 | 効果 (Whisper base で実測) |
|---|---|---|---|
| 1〜3 | ハイパス + 音量の正規化 | 常に有効 | 平均で同等以上 |
| 1〜3 | 定常ノイズのゲート | オフ | 強い定常ノイズで改善、他の人の声があると悪化 |
| 4 | 近くの声だけを送る | マイク: オン / スピーカー: オフ | 遠くの声だけのクリップの漏れ 13〜20/20 → 0〜2/20 (15 dB 以上小さい場合) |
| 5 | 折り返しの無い 16 kHz リサンプリング | 常に有効 | 小さい (誤差の範囲で改善) |
| 6 | スピーカーのステレオを平均でモノラル化 | 常に有効 | 大きい音での音割れを防ぐ |

## 1. 変更内容

確定した発話クリップを ASR (Whisper / Google / クラウド API) に送る直前に、
`src-python/models/transcription/audio_preprocess.py` で音声を整えるようにした。
numpy だけで実装しており、追加の依存やバンドルするモデルは無い。

| 処理 | 既定 | 内容 |
|---|---|---|
| ハイパスフィルタ (80 Hz) | 常に有効 | 低音のゴロゴロ・電源のハム音・DC オフセットを除去。音声は 85 Hz 未満にほぼエネルギーを持たない |
| 音量の正規化 | 常に有効 | 音声レベル (大きい方から 30% のフレームの RMS) を -20 dBFS に近づける。増幅は最大 +20 dB、ピークは -1 dBFS まで |
| スペクトルノイズゲート | **オフ** (設定で有効化) | 定常ノイズ (ファン・エアコン・マイクのサー音) を最大 12 dB 減衰 |

- 掛けるのは `AudioTranscriber._finalizeAndTranscribe` で ASR に渡す `AudioData` だけ。
  VAD / エネルギー閾値は元の音声で判定するので、調整済みの閾値には影響しない。
- VAD 経路が前後に付けるデジタル無音 (`VAD_PRE_PAD_MS` / `VAD_POST_PAD_MS`) は処理せずそのまま残す
  (含めると 0 がノイズフロアとみなされ、ゲートが効かなくなる)。
- 処理が例外を投げた場合は元の音声で文字起こしを続ける (発話を落とさない)。
- 処理時間: 15 秒のクリップで 16 kHz 約 45 ms、48 kHz 約 165 ms (CPU 4 コア、他の負荷あり)。

### ノイズゲートの仕組み

- ノイズのスペクトルはクリップ自身から推定する (分位点ベースのノイズ推定、Stahl et al., 2000)。
  各周波数ビンで音声が鳴っているのは一部の時間だけなので、時間方向の振幅の 20 パーセンタイルを
  ノイズフロアとみなす。間 (ま) の無いクリップでも推定できる。
- フロア +3 dB 以下のセルは最大まで減衰、+12 dB 以上はそのまま、その間はなだらかに。
  マスクは ±2 フレーム・±2 ビンで平滑化する (ミュージカルノイズ対策)。
- 減衰の上限は 12 dB。上限 20 dB では 12 dB より悪化した (下表)。

### 設定

- `MIC_NOISE_REDUCTION` / `SPEAKER_NOISE_REDUCTION` (既定 `False`)。ノイズゲートだけを切り替える。
- エンドポイント: `/get/data/{mic,speaker}_noise_reduction`、`/set/enable/…`、`/set/disable/…`
- 設定画面: 文字起こし → マイク / スピーカーの各セクション。VAD と同じく、次に文字起こしを開始したときから反映される。

## 2. 評価

### 方法

- モデル: faster-whisper `base` (VRCT の既定)、CPU int8。呼び出しは `LocalWhisperProvider` と同じ
  (beam 5、temperature 0、言語指定、avg_logprob < -0.8 / no_speech_prob > 0.6 のセグメントは捨てる、
  前 300 ms・後 500 ms の無音パディング)。
- 音声 (各 40 発話、1.5〜12 秒):
  - en: LibriSpeech (`hf-internal-testing/librispeech_asr_dummy`) — 英語の読み上げ
  - ja (JSUT): `japanese-asr/ja_asr.jsut_basic5000` — 日本語の読み上げ (クリーン)
  - ja (Reazon): `japanese-asr/ja_asr.reazonspeech_test` — 日本語のテレビ音声 (元から BGM・雑音あり)
- ノイズ (前後に 0.3 秒のノイズだけの区間を付けて混ぜる):
  - pink: ピンクノイズ + 50 Hz ハム (安いマイク・電源ノイズ)
  - stationary: ESC-50 の掃除機・飛行機・エンジン・雨・風・洗濯機・電車・ヘリ (ファン・エアコン相当)
  - babble: 同じデータセットの別の発話 4 つを重ねる (後ろで他の人が話している)
  - keyboard: ESC-50 のキーボード打鍵・マウスクリック
- 指標: en は WER、ja は CER (%)。括弧内は出力が空になった発話の数 (/40)。小さいほど良い。
- 40 発話なので、±2 ポイント程度の差は誤差の範囲。

### 結論

- **ハイパス + 正規化**: どのデータでも平均して処理なしと同等以上 (en 24.3→24.0、JSUT 32.8→32.9、
  Reazon 56.5→52.7)。後ろで他の人が話している条件でも悪化しなかった (測り直しで 38.6→35.2、
  49.5→49.2、59.6→57.9)。Google / クラウド API 向けには小さい声を持ち上げる効果もあるため、常に有効にした。
- **ノイズゲート**: 強い定常ノイズ (0 dB) では改善 (en 39.5→37.7、JSUT 45.6→43.5) するが、
  **後ろで他の人が話していると悪化**する (JSUT 49.5→53.6、Reazon 59.6→63.6、測り直しでは 69.0)。
  VRChat では他の人の声が重なるのが普通なので、既定はオフにし、ファンやエアコンの音が大きい
  ユーザーが自分で有効にする設定にした。
- **減衰の上限**: 20 dB は 12 dB より平均で悪い (en 24.6 vs 23.5、JSUT 35.0 vs 33.2)。
  強いノイズ除去が残す歪みは、Whisper にとってノイズそのものより扱いにくい。

### 測っていないもの

- Google / クラウド API での精度 (今回は Whisper base だけ)。
- Whisper の他のサイズ (small 以上はノイズに強く、差が小さくなる見込み)。
- 実際の VRChat の音声 (他プレイヤーのマイク品質、ワールドの BGM)。

## 3. 検討したが入れなかったもの

- **ニューラルなノイズ除去** (RNNoise、DeepFilterNet、DTLN): 人が聞いて自然になるよう学習された
  モデルで、ASR の前段に置くと Whisper のような頑健なモデルの精度はかえって下がることが多い
  (今回のゲートでも、強く掛けるほど悪化した)。ネイティブライブラリかモデルの同梱が必要になる。
  入れるなら今回と同じ方法で評価してから。
- **faster-whisper の `vad_filter`**: クリップ内の無音・ノイズ区間を切り捨てて幻覚を減らす機能。
  今回のノイズだけのクリップでは幻覚が出なかったため、効果を確かめられず見送った。

## 4. 近くの声だけを送る (遠くの話し声の除去)

`src-python/models/transcription/near_voice_gate.py`。設定 `MIC_NEAR_VOICE_ONLY` (既定 **True**) /
`SPEAKER_NEAR_VOICE_ONLY` (既定 False)。エンドポイント `/get/data/{mic,speaker}_near_voice_only`、
`/set/enable/…`、`/set/disable/…`。設定画面: 文字起こし → マイク / スピーカー。

### 考え方

VRChat では目的の声と遠くの声はレベルで分けられることが多い。マイクでは自分の口がマイクから数 cm で、
同じ部屋の人の声やスピーカーから漏れたゲーム音声は 20〜30 dB 小さい。スピーカー側では VRChat が
距離に応じて声を小さくする。

- 「近くの話者のレベル」= 直近 2 分間に近くの声と判定したクリップのレベル (大きい方から 10% の
  フレームの平均) の**中央値**。最初の 3 クリップは落とさずに基準づくりに使う。
- クリップのレベルが基準 −12 dB 未満なら、そのクリップは**文字起こし自体をしない** (他人の雑談を翻訳して送らない)。
- 近くの声を含むクリップでは、基準より十分小さいフレーム (遠くの声だけの区間) を 40 dB 減衰する。
  近くの声のフレームの前後 400 ms は残す (子音・語尾を削らないため)。
- ハイパスの後、音量の正規化の前に掛ける (レベルで判定するので元のレベルのまま見る)。

### 評価方法

Whisper base、各データ 40 発話 (第 2 節と同じ)。近くの話者は -26 dBFS。

- farDxN: 近くの話者の発話の前 1.5 秒・最中・後 1.0 秒に、D dB 小さい N 人の話し声 (同じデータセットの
  別の発話) を重ねる。さらに 2 発話ごとに、遠くの声だけのクリップ (2〜4 秒) を挟む。
  漏れ = 遠くの声だけのクリップで何か出力された数 (/20)。
- solo: 背景の声なし。shout10: 5 発話に 1 回、10 dB 大きい声 (笑い声・叫び声)。
- alt12: 近くの話者 2 人で、片方のマイクが 12 dB 小さい (交互に話す)。
- ゲートの状態はクリップをまたいで持ち越す (アプリと同じ)。時刻はクリップ長 + 1 秒ずつ進める。

### 結果 (誤り率 %、漏れ。最終的な設定: マージン 12 dB、中央値、ホールド 400 ms)

- 遠くの声が 15 dB 以上小さければ、遠くの声だけのクリップはほぼ全て落ちる (漏れ 13〜20 → 0〜2)。

- 4 人の雑談 (-15 dB) は、ゲートなしでも Whisper がほぼ無視する (重なった声は聞き取れないため)。ゲートで少し改善。

### 検討した設定

| 設定 | 結果 |
|---|---|
| 基準 = 最大値 + 減衰 (0.5 / 0.1 dB/秒) | 一度叫ぶと基準が跳ね上がり、普段の声が削られた (shout10: en 7.9 → 36.9、JSUT 22.3 → 60.4)。減衰 0.5 dB/秒ではクリップの間に基準が下がり、漏れが増えた |
| 基準 = 中央値 (採用) | shout10 の悪化がほぼ無くなった |
| マージン 8 / 10 / 12 / 15 dB | 8 は far10 も落とせる (漏れ 12 → 1) が、背景の声が無いときの悪化が大きい (JSUT 20.0 → 23.0)。15 は far15 で漏れが残る。12 は自分の声の大小に強い |
| 時間-周波数マスク (近くの話者のスペクトルより 20 dB 以上小さいセルを減衰) | 同時に話している遠くの声を減らす狙い。効果なし、背景の声が無いときに悪化 (Reazon 41.2 → 49.7)。不採用 |
| クリップ内で削る基準を −18 dB に (クリップを落とす基準は −12 dB のまま) | 平均 26.9 (ホールド 200 ms の 26.0 より悪い) |
| 減衰 20 dB (40 dB の代わり) | 平均 25.5 |
| ホールド 400 ms (採用) | 平均 24.9。背景の声が無いときの悪化が en ±0、JSUT +0.1、Reazon +1.9 に減った (200 ms では +3.9) |
| クリップ内では削らない (遠くの声だけのクリップを落とすだけ) | 背景の声が無いときは悪化ゼロ、漏れも同じく 0〜2/20 になるが、近くの話者の誤り率は改善しない (平均 31.4 = ゲートなしと同じ) |

(平均 = en / JSUT / Reazon × solo / far15x1 / far20x1 の 9 条件の誤り率の平均。ゲートなしは 31.4。)

### 限界

- **近くにいてもマイクの音量が小さい人は落ちる**。alt12 (近くの 2 人のマイクが 12 dB 違う) では、
  小さい方の発話の 3〜10/20 が文字起こしされなかった (誤り率 en 9.8 → 41.4、JSUT 20.9 → 42.9、
  Reazon 40.2 → 50.3)。レベルだけでは「マイクの小さい近くの人」と「遠くの人」を区別できない。
  マイク側では近くの話者は自分 1 人なので問題になりにくいが、スピーカー側では起こりうるため、
  スピーカー側は既定でオフにした。
- 近くの話者と同時に話された遠くの声は分離できない (時間方向に切ることしかできない)。
- 遠くの声が 10 dB 程度しか小さくない場合はほぼ通る。

## 5. 16 kHz へのリサンプリング (折り返しの除去)

`audioop.ratecv` はローパスフィルタを掛けずに間引くため、48 kHz → 16 kHz で 8 kHz より上の成分が
**そのままのレベルで**音声帯域に折り返していた (実測: 9 kHz → 7 kHz、12 kHz → 4 kHz、15 kHz → 1 kHz、
いずれも 0 dB)。使っていたのは次の経路:

- Whisper・OpenAI 互換 API・Deepgram へ送る音声 (`get_raw_data(convert_rate=16000)`)。
  エネルギー閾値方式 (既定) ではデバイスのレート (Windows では通常 48 kHz) のまま届くので、毎回通っていた。
- VAD 方式の正規化 (`audio_vad.Pcm16MonoNormalizer`)。全エンジン (Google も) と VAD 自体がこの音声を使う。

Google にはデバイスのレートのまま送っており (`get_flac_data(convert_rate=None)`)、影響していない。

変更 (`src-python/models/transcription/resample.py`):

- Google 以外のエンジンでは、`AudioTranscriber` がクリップ全体を FFT で 16 kHz にリサンプリングしてから渡す
  (7.2〜8 kHz でなだらかに減衰。後段の `convert_rate=16000` は何もしなくなる)。15 秒で約 30 ms。
- VAD 方式の正規化では、`ratecv` の前にストリーミングの FIR ローパス (カイザー窓、301 タップ @48 kHz、
  阻止域 約 80 dB、遅延 約 3 ms) を掛ける。
- 8 kHz より上のトーンは、どちらでも -95 dB 以下になる (変更前は 0 dB)。通過域 (〜7 kHz) は ±0.7 dB 以内。

評価 (JSUT をネイティブの 48 kHz のまま 40 発話、Whisper base、CER %):

| 条件 | ratecv (変更前) | soxr VHQ (参照) | FFT (Whisper/API 経路) | FIR + ratecv (VAD 経路) |
|---|---|---|---|---|
| クリーン | 21.4 | 21.2 | 19.9 | 21.4 |
| マイクのサー音 (白色、SNR 20 dB) | 20.5 | 19.9 | 19.3 | 19.9 |

精度への効果は小さく、40 発話では誤差の範囲 (Whisper は折り返しに強い。実際の音声は 8 kHz より上の
エネルギーが小さい)。信号処理として正しく、処理も軽く、平均で悪化しないので入れた。

## 6. スピーカー音声のステレオ → モノラル

エネルギー閾値方式 (既定) のスピーカー音声は、WAV に書いて `speech_recognition.AudioFile` で読み直して
おり、ステレオ (ループバックの既定) は `audioop.tomono(…, 1, 1)` = **L+R の合計**になっていた。
ゲーム音声が -6 dBFS を超えると 32767 に張り付いて音割れする。マイク側は以前に平均へ直してあったので、
スピーカー側も同じ平均にした (`AudioTranscriber._monoAudioData`)。
